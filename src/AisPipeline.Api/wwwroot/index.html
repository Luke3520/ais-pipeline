A rule either rejects a row into quarantine or keeps it and flags the doubt — there is no third option, so both columns are shown. A rule that ran and never fired prints zero and is greyed: silence and absence are different claims. Counts are over what the store holds, not over lines read.

Port calls

    idmmsiarrived (UTC) waiting hworking hunclassified h extentnearest port
    loading…

    Ordered by total duration, not chronologically. A port marked like this is the nearest one, not necessarily where the vessel was: a World Port Index record is a single nominal point near the harbour entrance, so the distance is shown with every name and never omitted. A call marked open has an unknown true extent — it touches a coverage gap or the edge of the window — so its hours are the sum of what was observed and a lower bound, shown as 42.2. A zero is left unmarked: "at least zero hours" says nothing, and the extent column already states it.

    2.7 is a lower bound, not a measurement — the stop touches a coverage gap or the edge of the ingested window, so its true extent is unknown. ? is a drift computed from too few surviving fixes to mean anything. Neither is shown as a plain number.

    Not on this page

    ais laytime and ais reconcile — the laytime statement and the comparison against a Statement of Facts — are CLI verbs with no HTTP endpoint. Reconciliation needs a document uploaded, and a write surface would make authentication non-deferrable, so it is deliberately absent rather than quietly missing (ADR-0037, ADR-0017).
