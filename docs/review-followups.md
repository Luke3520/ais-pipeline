| 2026-09-12 | `src/AisPipeline.Core/Ports/IAisQueries.cs` | (self) | `ListFixes` and `GetStopsForVessels` were **deleted**: zero call sites, and both justified by a use that did not exist — `GetStopsForVessels` documented itself as "the batched shape, again for DataLoader" while no DataLoader used it. | 2026-09-12 | `src/AisPipeline.Core/Query/ReadModels.cs` | (self) | **Declined, deliberately.** `StoredStop` nulls a figure it will not stand behind; `StoredPortCall` does not, so an incomplete call's `WaitingHours` is a lower bound typed as a measurement. Making it nullable was considered and rejected: `IsComplete` already carries the signal and the API already returns it, so the change buys compiler enforcement on top of an existing documented flag, at the cost of `waitingHours` going `number` -> `number \| null` for every existing client. An earlier note here claimed the change "reaches into laytime" -- it does not. `VoyageTimeline` reads the domain `PortCall`, rebuilt from phases; the read model never enters the laytime calculation, only one CLI display line. The blast radius is five sites, one of them a public contract. Revisit if a client is ever found summing `waitingHours` across incomplete calls, which is the only way this bites. |

| 2026-09-11 | `src/AisPipeline.Core/Detection/StopDetector.cs` | (self, M2) | A berthed vessel briefly exceeding 1.0 kn closes its stop, so one berth stay can split into many. A debounce would fix 20 of 447 splits and was **not** implemented -- waiting and working hours are barely affected (mean 0.49 h per call unaccounted). Revisit only if laytime needs finer granularity. |
